# Computer-use and browser-control audit

Audit date: 2026-08-20. Implementation target: version 0.11.0.

Earlier audits stay in this document rather than being replaced, so a row's history is readable in one place. The 2026-08-18 audit (version 0.9.0) is the baseline; the 2026-08-19 audit (version 0.10.0) revised the rows marked with a `0.10:` prefix; this audit adds or revises the rows marked `0.11:`. An unmarked row describes the 0.9 baseline that both later versions carry forward unchanged.

Version 0.11 covers two bodies of work:

1. **Cross-origin iframe (OOPIF) support** — a shared `extension/dom-core.js`, a read-only in-frame `extension/frame-agent.js`, frame-scoped refs, frame provenance on observations and elements, and a family of frame error codes. Implemented and contract-proven; *not* live-proven, and the rows below say exactly which CDP behaviours that leaves open.
2. **The dialog/lease defect fix** — the 0.10 dialog interception was found broken by a live run against the packaged 0.10.0 artifacts, recorded in [../evidence/v0.10.0/README.md](../evidence/v0.10.0/README.md). Version 0.11 closes it.

This audit separates implemented behavior, benchmark influence, and unimplemented isolation. A delivered input event is never sufficient proof: the target must still match the observation, the authority must still be live, and an application-owned result should be observed whenever the platform exposes one.

## Evidence hierarchy

1. Local source and tests define what this release implements.
2. Live screenshots plus machine-readable results establish that a built artifact exercised that implementation.
3. Chromium/platform source and vendor documentation establish external API behavior.
4. Pinned open-source implementations and papers provide design benchmarks.
5. Community reports suggest failure cases but do not prove platform properties.

The detailed source inventory, pinned commits, empirical ChatGPT/Claude package hashes, and research conclusions are in [COMPUTER_USE_RESEARCH.md](COMPUTER_USE_RESEARCH.md).

“SOTA” is therefore a vector, not a release badge. Version 0.9 materially upgraded controller visibility, authority lifetime, stale-state refusal, pointer evidence, and bounded viewing. The project remains deliberately behind native-overlay projects on physical-desktop visualization and behind RDP/VM designs on security isolation.

## Remaining boundaries

- Chrome's native warning depends on an actual non-suppressed `chrome.debugger` attachment. A screenshot of only the page pill does not prove it.
- Chrome's Cancel action can terminate all debugger clients owned by that extension. Version 0.9 intentionally holds only one controlled-tab attachment.
- The page overlay cannot run on restricted `chrome://`, `edge://`, extension, or protected pages. Those pages also remain outside extension control.
- Open shadow roots are covered. Version 0.11 adds cross-origin iframe semantic merging over `Target.setAutoAttach` child sessions, but it is proven only by the Rust and Node contract suites; five CDP behaviours (child-session event delivery, `sessionId` command routing, `DOM.getBoxModel`'s coordinate space, root-session input hit-testing into an OOPIF, and isolated-world survival) still need a live-Chrome rig before cross-origin semantic parity may be claimed. Every one of them degrades to a refusal, and a Chrome that does not route `sessionId` disables frame support for the lease via a discriminating routing probe.
- Same-origin and same-process iframes are still not merged, and only `page.click` and `page.hover` act inside a frame. `page.fill` and `page.select` refuse a frame-scoped ref with `FRAME_ACTION_UNSUPPORTED`; `page.key`, `page.scroll`, `page.typeText`, and `page.clickAt` take no `ref` at all, so they simply have no frame-scoped form. Unmerged frames are reported as `same_process_frame` rather than silently dropped.
- The 0.11 lease's `Target.setAutoAttach` extends the single debugger attachment to the controlled tab's out-of-process iframe targets. Non-`iframe` targets are detached on arrival, child sessions never get their own attachment, and the in-frame agent is read-only in a nonce-keyed isolated world — but a third-party embed is now inside the attachment's blast radius in a way it was not before 0.10. See [../SECURITY.md](../SECURITY.md).
- A pending dialog no longer revokes the lease, but the guarantee is scoped: it covers renderer-blocked probes, dispatches, held-input releases, and service-worker recovery. An explicit stop, a human pause, the lease TTL, a recovered candidate that fails the restart's own fail-closed rules, and any failure observed with no dialog pending all still revoke — and nothing is forgiven permanently, because the record is cleared the moment the dialog resolves and the very next check catches a document that really did change.
- The browser extension has broad HTTP, HTTPS, and optional file authority in Full Access. Loopback authentication, stale-state checks, and visible control do not make prompt-injected page content trustworthy.
- macOS background delivery depends on private SkyLight interfaces. Unsupported OS/framework combinations must refuse rather than switch to global input.
- Windows UIA compilation is not representative Windows runtime proof. A native Windows fixture remains required before a new UI framework/action combination is marked supported.
- Exact-window sharing prevents unrelated-window capture but does not isolate memory, credentials, app state, or OS permissions from the user's session.
- Deliberately deferred beyond 0.11: same-process iframe merging, frame-scoped text entry and scrolling, frame-aware `page.clickAt`, PUSV-style pixel-diff preflight, an MCP facade, set-of-marks visual annotation, a compressed screencast transport, and an isolated OS input session. Each stays a stated boundary rather than a partial claim.

## Acceptance rule

Do not mark a versioned deployment—0.9 then, 0.10, now 0.11—complete until the release-specific evidence exists, the full Rust/extension contract suite passes, both target artifact sets are verified, and the real-Chrome Cancel path proves fail-closed behavior. A transport-level success or a single screenshot is diagnostic evidence only.

Version 0.10 is the worked example of why that rule is written this way round. Its contract suite was green, its release was reproducible and attested, and its dialog gate was still broken on every real browser it met, because the suite injected the pending dialog before the gate instead of racing it. A green suite therefore licenses a live run; it never substitutes for one. For 0.11 this means the frame rows stay marked harness-proven until the live bundle exists, and the dialog row stays a repair rather than a proven claim until the failing 0.10 scenario has been re-run and recorded green.
