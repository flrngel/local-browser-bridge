# Computer-use and browser-control audit

Audit date: 2026-08-21. Implementation target: version 0.12.1. The evidence chain includes the published 0.11.0 browser bundle, the exact published 0.11.1 boundary and macOS-helper runs, and an explicitly unpublished 0.11.2 browser candidate: [../evidence/v0.11.1/README.md](../evidence/v0.11.1/README.md). Version 0.12.1 replaces the helper's timer-driven live snapshots with native exact-window streams; it remains a source candidate until packaged live evidence exists.

Earlier audits stay in this document rather than being replaced, so a row's history is readable in one place. The 2026-08-18 audit (version 0.9.0) is the baseline; the 2026-08-19 audit (version 0.10.0) revised the rows marked with a `0.10:` prefix; this audit adds or revises the rows marked `0.11:`, `0.11.1:`, `0.11.2:`, and `0.12:`. An unmarked row describes the 0.9 baseline carried forward unless a later entry says otherwise.

Version 0.11 covers two bodies of work:

1. **Cross-origin iframe (OOPIF) support** — a shared `extension/dom-core.js`, a read-only in-frame `extension/frame-agent.js`, frame-scoped refs, frame provenance on observations and elements, and a family of frame error codes. Implemented, contract-proven, and now live-proven on one genuine out-of-process iframe at depth 1: observation, merging, coordinate translation, and a trusted click that landed inside the child renderer. The rows below say exactly what that run settled and what it left open.
2. **The dialog/lease defect fix** — the 0.10 dialog interception was found broken by a live run against the packaged 0.10.0 artifacts, recorded in [../evidence/v0.10.0/README.md](../evidence/v0.10.0/README.md). Version 0.11 closes it, and the exact failing scenario has been re-run green on the packaged 0.11.0 build.

Version 0.11.1 is a one-defect patch found by the same live method:

3. **HTTP status derived from the error taxonomy** — the Stop-button run recorded a human pause being reported to REST clients as HTTP 500. A 500 says the local server faulted and invites a retry; the only thing that resolves a human pause is a person pressing **Resume**. Every connector-originated failure now takes its status from its taxonomy class, so a human pause answers 423 Locked and no connector state can be reported as a bridge fault. See the `Structured error taxonomy` row.

Version 0.11.2 is another live-found boundary repair:

4. **Recursive OOPIF discovery** — an exact published 0.11.1 run rendered two nested cross-origin targets but merged only the first because `Target.setAutoAttach` is direct-only. Version 0.11.2 routes nested target lifecycle events and recursively arms only verified child sessions within the existing depth, count, and shared-time bounds. A packaged local candidate passed 22 of 22 live checks, including a depth-two trusted click. It is candidate evidence, not immutable release evidence.

Version 0.12.1 addresses the native-sharing architecture gap:

5. **Persistent native exact-window capture** — `computer.share.start` now owns one ScreenCaptureKit `SCStream` on macOS or a project-owned Windows Graphics Capture `CreateFreeThreaded` frame pool on a dedicated MTA owner thread. Each native callback writes to a capacity-one source mailbox with its own sequence/drop metrics; PNG conversion and the acknowledged transport mailbox remain separately bounded. Capture is no longer stopped by the controller mutex during an action, but publication and the composited pointer still resume after command serialization. This is shared-session operation with before/after input invariant checks, not a VM, RDP desktop, PiP view, native picker, or separate input seat; matching samples do not prove zero interruption. Source contracts are green; packaged macOS and real-Windows runtime evidence is still required.

**Evidence correction:** earlier rows described Chrome for Testing as suppressing Chrome's native debugger warning. The screenshots establish only that the warning was absent. Chromium's implementation documents explicit suppression for a silent-debugger flag and policy-installed extensions; the evidence did not establish either condition. Every such historical phrase below should therefore be read as “absent from that capture,” not as a Chrome for Testing product guarantee.

This audit separates implemented behavior, benchmark influence, and unimplemented isolation. A delivered input event is never sufficient proof: the target must still match the observation, the authority must still be live, and an application-owned result should be observed whenever the platform exposes one.

## Evidence hierarchy

1. Local source and tests define what this release implements.
2. Live screenshots plus machine-readable results establish that a built artifact exercised that implementation.
3. Chromium/platform source and vendor documentation establish external API behavior.
4. Pinned open-source implementations and papers provide design benchmarks.
5. Community reports suggest failure cases but do not prove platform properties.

The detailed source inventory, pinned commits, empirical ChatGPT/Claude package hashes, and research conclusions are in [COMPUTER_USE_RESEARCH.md](COMPUTER_USE_RESEARCH.md).

| Computer live view | Native helper + server | 0.12: persistent exact-window SCStream/WGC source with a requested 1–10 FPS maximum cadence, capacity-one native and encoded mailboxes, separate source/transport sequence and drop metrics, and default OS-controlled capture indication | One selected window, programmatic selection, PNGs capped at 1,000,000 pixels, no guaranteed delivery rate or every-sample pointer animation, no native picker/PiP; it is not a virtual display, RDP session, VM, video codec, or separate input seat |

These surfaces are intentionally independent. The Chrome warning proves a debugger attachment. The page pill provides product state and a human Stop action. The helper pointer explains model attention inside returned images. None alone proves end-task success.

“SOTA” is therefore a vector, not a release badge. Version 0.9 materially upgraded controller visibility, authority lifetime, stale-state refusal, pointer evidence, and bounded viewing. Version 0.10 adds condition waits, epoch-bound batches, dialog interception, idempotent command replay, a structured recovery taxonomy, normalized coordinates, Host-header hardening, and ack-paced latest-frame-wins sharing. Version 0.11 adds cross-origin iframe observation and frame-scoped click/hover, and repairs the 0.10 dialog gate that a live run proved was still surrendering the lease. Version 0.11.1 aligns connector HTTP status with the taxonomy. Version 0.11.2 makes OOPIF discovery genuinely recursive. Version 0.12 replaces timer snapshots with persistent native exact-window capture while retaining target-routed input. The project remains deliberately behind native-overlay projects on physical-desktop visualization and behind RDP/VM designs on security isolation; 0.12 is not a release badge until its packaged platform runs exist.

## Remaining boundaries

- Chrome's native warning depends on an actual non-suppressed `chrome.debugger` attachment. The exact published 0.11.1 stock-Chrome run now proves the warning and independent page pill simultaneously; a screenshot of only the page pill would still not prove it.
- Chrome's Cancel action can terminate all debugger clients owned by that extension. Local Browser Bridge holds one controlled-tab attachment, and the exact published 0.11.1 run now proves the native trigger: the unique PID-scoped Cancel click produced `canceled_by_user`, revoked the lease, removed the overlay, latched `humanPaused`, and refused the next remote start. The run used an intentionally ephemeral CDP-installed extension, so persistence across a full Chrome restart remains unproven.
- The human-pause latch is proven live through both human surfaces exercised so far: the in-page Stop click produced `released_by_user`, while native Chrome Cancel produced `canceled_by_user`; both revoked the lease and refused subsequent remote control with `HUMAN_CONTROL_PAUSED`. The extension popup's **Release control** is the remaining unexercised release surface.
- Since 0.11.1 a connector failure's HTTP status is derived from its taxonomy class, so a human pause is 423 rather than 500. Statuses the server produces for its own refusals are unchanged, and `INVALID_SANITIZER_STATE` remains the one 500 the API can answer. Clients that branched on 500 to mean "retry or alert" must branch on the taxonomy instead.
- The page overlay cannot run on restricted `chrome://`, `edge://`, extension, or protected pages. Those pages also remain outside extension control.
- Open shadow roots are covered. The published 0.11.0 bundle proves one genuine depth-one OOPIF: child-session routing, provenance, coordinate translation, isolated-world proof, and a trusted click. The exact published 0.11.1 boundary run additionally proves a top-level `same_process_frame` report and live `FRAME_ACTION_UNSUPPORTED`, while its 17/19 result exposes the non-recursive depth-two defect. Version 0.11.2 recursively arms only routing-verified child sessions; a local packaged candidate passed 22/22 with a depth-two merge and trusted click. This is not cross-origin semantic parity or published repair proof. Same-document-navigation survival remains harness-only, nested in-process owners are not completely reported, and the exact `session_routing_unverified` result is an explicitly simulated stripped-session counterfactual rather than an identified Chrome behavior. Chrome 118–124 reject child-session routing because the schema lacks `sessionId`; Chrome 125 added the routed form.
- Same-origin and same-process iframes are still not merged, and only `page.click` and `page.hover` act inside a frame. `page.fill` and `page.select` refuse a frame-scoped ref with `FRAME_ACTION_UNSUPPORTED`; `page.key`, `page.scroll`, `page.typeText`, and `page.clickAt` take no `ref` at all. Top-document in-process iframe owners are reported as `same_process_frame`; an in-process owner nested inside an attached child is a stated reporting gap because the frame agent does not publish nested owners.
- The 0.11.2 lease recursively applies `Target.setAutoAttach` to each routing-verified child session because the CDP setting is direct-only. Non-`iframe`, unknown-parent, blank, over-count, and over-depth targets are detached on arrival; nested detach removes the recorded subtree; child sessions still ride the one controlled-tab debugger attachment; and the in-frame agent remains read-only in a nonce-keyed isolated world. A third-party embed is inside the attachment's blast radius in a way it was not before 0.10. See [../SECURITY.md](../SECURITY.md).
- A pending dialog no longer revokes the lease, but the guarantee is scoped: it covers renderer-blocked probes, dispatches, held-input releases, and service-worker recovery. An explicit stop, a human pause, the lease TTL, a recovered candidate that fails the restart's own fail-closed rules, and any failure observed with no dialog pending all still revoke — and nothing is forgiven permanently, because the record is cleared the moment the dialog resolves and the very next check catches a document that really did change.
- The browser extension has broad HTTP, HTTPS, and optional file authority in Full Access. Loopback authentication, stale-state checks, and visible control do not make prompt-injected page content trustworthy.
- macOS background delivery depends on private SkyLight interfaces. Unsupported OS/framework combinations must refuse rather than switch to global input.
- Windows UIA compilation is not representative Windows runtime proof. A native Windows fixture remains required before a new UI framework/action combination is marked supported.
- Exact-window sharing prevents unrelated-window capture but does not isolate memory, credentials, app state, or OS permissions from the user's session.
- Deliberately deferred beyond 0.12.1: native content picker/PiP, same-process iframe merging, frame-scoped text entry and scrolling, frame-aware `page.clickAt`, PUSV-style pixel-diff preflight, an MCP facade, set-of-marks visual annotation, a compressed video transport, and an isolated OS input session. Each stays a stated boundary rather than a partial claim.

## Acceptance rule

Do not mark a versioned deployment—including the 0.12.1 candidate—complete until release-specific evidence exists, the full Rust/extension contract suite passes, both target artifact sets are verified, and the relevant real-browser and native-helper paths prove fail-closed behavior. For 0.12, that adds a packaged persistent-stream run, target-close/stop cleanup, source-versus-transport pacing evidence, unchanged desktop invariants on macOS, and a real interactive-Windows capture/input run before broad Windows claims. A transport-level success, developer candidate, or single screenshot is diagnostic evidence only.

For the exact published 0.11.1 artifacts, both halves of the real-Chrome Cancel clause are now satisfied. A unique PID-scoped native click supplied the browser-owned trigger; `chrome.debugger.onDetach` reported `canceled_by_user`; the lease and overlay disappeared; `humanPaused` latched; and the next remote start was refused with HTTP 423 `HUMAN_CONTROL_PAUSED`. This does not turn the unpublished 0.11.2 candidate into a deployment and does not prove full-browser-restart persistence: the stock-Chrome evidence installation was intentionally ephemeral and removed at cleanup.

Version 0.10 is the worked example of why that rule is written this way round. Its contract suite was green, its release was reproducible and attested, and its dialog gate was still broken on every real browser it met, because the suite injected the pending dialog before the gate instead of racing it. A green suite therefore licenses a live run; it never substitutes for one. Version 0.11.1 repeated the lesson twice: a Stop-button run found the HTTP 500 taxonomy/status mismatch, and the later boundary run found that a manually injected depth-two harness had hidden the root-only auto-attach defect. The 0.11.2 contracts now drive dynamic child events and the final local packaged candidate passes the live nested scenario, including the lease-sticky negative-routing behavior in contracts, but immutable release proof, popup Release, full-browser-restart persistence after Cancel, and Windows UIA runtime remain explicit gates. The exact published Chrome Cancel and macOS-helper paths are now live-proven rather than inferred from contracts.
