# Computer-use and browser-control audit

Audit date: 2026-08-20. Implementation target: version 0.11.1, backed by a live evidence bundle recorded against the published 0.11.0 release artifacts: [../evidence/v0.11.0/README.md](../evidence/v0.11.0/README.md), two runs, 32 of 32 live checks passed.

Earlier audits stay in this document rather than being replaced, so a row's history is readable in one place. The 2026-08-18 audit (version 0.9.0) is the baseline; the 2026-08-19 audit (version 0.10.0) revised the rows marked with a `0.10:` prefix; this audit adds or revises the rows marked `0.11:` and `0.11.1:`. An unmarked row describes the 0.9 baseline that both later versions carry forward unchanged.

Version 0.11 covers two bodies of work:

1. **Cross-origin iframe (OOPIF) support** — a shared `extension/dom-core.js`, a read-only in-frame `extension/frame-agent.js`, frame-scoped refs, frame provenance on observations and elements, and a family of frame error codes. Implemented, contract-proven, and now live-proven on one genuine out-of-process iframe at depth 1: observation, merging, coordinate translation, and a trusted click that landed inside the child renderer. The rows below say exactly what that run settled and what it left open.
2. **The dialog/lease defect fix** — the 0.10 dialog interception was found broken by a live run against the packaged 0.10.0 artifacts, recorded in [../evidence/v0.10.0/README.md](../evidence/v0.10.0/README.md). Version 0.11 closes it, and the exact failing scenario has been re-run green on the packaged 0.11.0 build.

Version 0.11.1 is a one-defect patch found by the same live method:

3. **HTTP status derived from the error taxonomy** — the Stop-button run recorded a human pause being reported to REST clients as HTTP 500. A 500 says the local server faulted and invites a retry; the only thing that resolves a human pause is a person pressing **Resume**. Every connector-originated failure now takes its status from its taxonomy class, so a human pause answers 423 Locked and no connector state can be reported as a bridge fault. See the `Structured error taxonomy` row.

This audit separates implemented behavior, benchmark influence, and unimplemented isolation. A delivered input event is never sufficient proof: the target must still match the observation, the authority must still be live, and an application-owned result should be observed whenever the platform exposes one.

## Evidence hierarchy

1. Local source and tests define what this release implements.
2. Live screenshots plus machine-readable results establish that a built artifact exercised that implementation.
3. Chromium/platform source and vendor documentation establish external API behavior.
4. Pinned open-source implementations and papers provide design benchmarks.
5. Community reports suggest failure cases but do not prove platform properties.

The detailed source inventory, pinned commits, empirical ChatGPT/Claude package hashes, and research conclusions are in [COMPUTER_USE_RESEARCH.md](COMPUTER_USE_RESEARCH.md).

## Indicator audit

| Surface | Owner | Version 0.9 behavior | Honest boundary |
|---|---|---|---|
| Chrome debugger warning | Chrome browser chrome | One held `chrome.debugger` attachment keeps **Local Browser Bridge started debugging this browser** visible during the lease | Chrome may suppress the warning for explicit silent-debugger flags or policy-installed extensions; the extension cannot paint or override this UI |
| Page control indicator | Extension content script | Closed-shadow pill states that the bridge is using the tab, shows turn/move counters, and provides a trusted Stop button | It is page content, not Chrome UI; it exists only on scriptable HTTP(S)/file pages |
| Browser synthetic pointer | Extension + CDP | Bounded Bézier/spring movement dispatches real trusted CDP mouse-move events and updates the page pointer before click arrival | It is not the hardware pointer or an OS overlay |
| Computer synthetic pointer | Native helper + image compositor | Session-owned, window-scoped state is moved through exact-window background delivery and composited into returned PNG frames | Version 0.9 has no native click-through desktop overlay; shared frames show settled state, not every intermediate sample |
| Computer live view | Native helper + server | Repeated exact-window observations at 1–10 FPS with monotonic sequence and producer-blocking capture | It is not a virtual display, RDP session, VM, video codec, or separate input seat |

These surfaces are intentionally independent. The Chrome warning proves a debugger attachment. The page pill provides product state and a human Stop action. The helper pointer explains model attention inside returned images. None alone proves end-task success.

“SOTA” is therefore a vector, not a release badge. Version 0.9 materially upgraded controller visibility, authority lifetime, stale-state refusal, pointer evidence, and bounded viewing. Version 0.10 adds condition waits, epoch-bound batches, dialog interception, idempotent command replay, a structured recovery taxonomy, normalized coordinates, Host-header hardening, and ack-paced latest-frame-wins sharing. Version 0.11 adds cross-origin iframe observation and frame-scoped click/hover, and repairs the 0.10 dialog gate that a live run proved was still surrendering the lease. Neither 0.11 change moves this table: the frame work narrows the gap to driver-grade automation on reachable page content — including, since the 0.11 live bundle, reachable cross-origin content, though what that bundle proved is one real out-of-process iframe at depth 1 in one Chrome build, not general frame parity — and the dialog fix restores behavior 0.10 had already claimed rather than adding any. Version 0.11.1 moves it even less: deriving a failure's HTTP status from its taxonomy class corrects what the bridge *says* about a state it already handled correctly. The project remains deliberately behind native-overlay projects on physical-desktop visualization and behind RDP/VM designs on security isolation.

## Remaining boundaries

- Chrome's native warning depends on an actual non-suppressed `chrome.debugger` attachment. A screenshot of only the page pill does not prove it.
- Chrome's Cancel action can terminate all debugger clients owned by that extension. Version 0.9 intentionally holds only one controlled-tab attachment. Cancel itself remains unproven live and cannot be proven the way the in-page Stop button was: it is browser chrome, and a dispatched `Input.dispatchMouseEvent` only ever reaches a renderer.
- The human-pause latch is proven live for the in-page Stop button: a real dispatched click revoked the lease `released_by_user`, set `humanPaused`, and left remote start and observe refused with `HUMAN_CONTROL_PAUSED` until a person resumes. Two neighbours of that claim are not proven live — Chrome's Cancel button and the extension popup's **Release control** — and the packaged screenshots show the page overlay disappearing, not the native Chrome warning, which Chrome for Testing suppresses.
- Since 0.11.1 a connector failure's HTTP status is derived from its taxonomy class, so a human pause is 423 rather than 500. Statuses the server produces for its own refusals are unchanged, and `INVALID_SANITIZER_STATE` remains the one 500 the API can answer. Clients that branched on 500 to mean "retry or alert" must branch on the taxonomy instead.
- The page overlay cannot run on restricted `chrome://`, `edge://`, extension, or protected pages. Those pages also remain outside extension control.
- Open shadow roots are covered. Version 0.11 adds cross-origin iframe semantic merging over `Target.setAutoAttach` child sessions, and the 0.11 live bundle proves it on one genuine out-of-process iframe at depth 1 — discovery, merging with frame provenance, coordinate translation, and a trusted click the child renderer saw as `isTrusted`. The five CDP behaviours that design assumed (child-session event delivery, `sessionId` command routing, `DOM.getBoxModel`'s coordinate space, root-session input hit-testing into an OOPIF, and isolated-world survival) are confirmed in practice for that case. That is not cross-origin semantic parity; the accurate residue is what one depth-1 frame in one Chrome build could not show: the negative routing probe, a `same_process_frame` skip and a live `FRAME_ACTION_UNSUPPORTED` refusal, nesting past depth 1, and isolated-world survival across a frame's own same-document navigation. Every one of those still degrades to a refusal, and a Chrome that does not route `sessionId` disables frame support for the lease via the discriminating routing probe.
- Same-origin and same-process iframes are still not merged, and only `page.click` and `page.hover` act inside a frame. `page.fill` and `page.select` refuse a frame-scoped ref with `FRAME_ACTION_UNSUPPORTED`; `page.key`, `page.scroll`, `page.typeText`, and `page.clickAt` take no `ref` at all, so they simply have no frame-scoped form. Unmerged frames are reported as `same_process_frame` rather than silently dropped.
- The 0.11 lease's `Target.setAutoAttach` extends the single debugger attachment to the controlled tab's out-of-process iframe targets. Non-`iframe` targets are detached on arrival, child sessions never get their own attachment, and the in-frame agent is read-only in a nonce-keyed isolated world — but a third-party embed is now inside the attachment's blast radius in a way it was not before 0.10. See [../SECURITY.md](../SECURITY.md).
- A pending dialog no longer revokes the lease, but the guarantee is scoped: it covers renderer-blocked probes, dispatches, held-input releases, and service-worker recovery. An explicit stop, a human pause, the lease TTL, a recovered candidate that fails the restart's own fail-closed rules, and any failure observed with no dialog pending all still revoke — and nothing is forgiven permanently, because the record is cleared the moment the dialog resolves and the very next check catches a document that really did change.
- The browser extension has broad HTTP, HTTPS, and optional file authority in Full Access. Loopback authentication, stale-state checks, and visible control do not make prompt-injected page content trustworthy.
- macOS background delivery depends on private SkyLight interfaces. Unsupported OS/framework combinations must refuse rather than switch to global input.
- Windows UIA compilation is not representative Windows runtime proof. A native Windows fixture remains required before a new UI framework/action combination is marked supported.
- Exact-window sharing prevents unrelated-window capture but does not isolate memory, credentials, app state, or OS permissions from the user's session.
- Deliberately deferred beyond 0.11.1: same-process iframe merging, frame-scoped text entry and scrolling, frame-aware `page.clickAt`, PUSV-style pixel-diff preflight, an MCP facade, set-of-marks visual annotation, a compressed screencast transport, and an isolated OS input session. Each stays a stated boundary rather than a partial claim.

## Acceptance rule

Do not mark a versioned deployment—0.9 then, 0.10, 0.11, now 0.11.1—complete until the release-specific evidence exists, the full Rust/extension contract suite passes, both target artifact sets are verified, and the real-Chrome Cancel path proves fail-closed behavior. A transport-level success or a single screenshot is diagnostic evidence only.

That last clause has two halves, and exactly one of them is now satisfied. The fail-closed *consequences* of a human seizing control are proven live on a packaged build: the in-page Stop button, clicked with a genuine dispatched input event, revoked the lease, latched `humanPaused`, and left both a remote `browser.control.start` and a remote `page.observe` refused with `HUMAN_CONTROL_PAUSED` while the overlay left the page. The *Chrome Cancel trigger* is still not proven: `chrome.debugger.onDetach` is a different entry point into that same revocation path, Cancel is browser chrome that no dispatched page input can press, and only real OS-level input on a host with macOS assistive access can settle it. So the rule is not discharged by the Stop proof; it is half-discharged, and the outstanding half is named rather than quietly rewritten.

Version 0.10 is the worked example of why that rule is written this way round. Its contract suite was green, its release was reproducible and attested, and its dialog gate was still broken on every real browser it met, because the suite injected the pending dialog before the gate instead of racing it. A green suite therefore licenses a live run; it never substitutes for one — that rule stands whatever any later bundle records. Both conditions it imposed on 0.11 are now met: the [0.11 live bundle](../evidence/v0.11.0/README.md) exists, so the frame rows are no longer harness-proven for the depth-1 cross-origin case, and the failing 0.10 scenario has been re-run and recorded green on a packaged build, so the dialog row is a proven repair rather than a pending one. What that bundle did not exercise stays a stated boundary and not a claim: the negative routing probe, a same-process skip and a live `FRAME_ACTION_UNSUPPORTED` refusal, nested frames, the two dialog routes only the harnesses drive, Chrome Cancel, the extension popup's Release control, and the desktop helper. Version 0.11.1 is the same lesson at smaller scale: the contract suite was green on a taxonomy it had itself pinned, and it took a live click on the Stop button to notice that the resulting refusal was being reported as a 500.
